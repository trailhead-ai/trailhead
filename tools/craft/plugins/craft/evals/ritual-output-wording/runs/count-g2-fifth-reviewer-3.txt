## Findings
- [Critical] No task has a test contract: AC1, AC2 and AC5 turn on date and rounding boundaries, and nothing pins them, so a fee or overdue bug ships unseen. Suggested: give each task failing-first tests, with an injected clock, covering either side of midnight, the cap, the £10.00 threshold, and a repeat run.
- [Critical] Nightly job is not idempotent and has no failure signal: a rerun or crash mid-batch double-charges some borrowers or leaves others uncharged, and a missed run leaves flags stale and blocks wrong with no alert. Suggested: key charges on (loan, fee date) in a unique ledger, commit per loan, make runs replayable with catch-up, and alert on last-success age.
- [Important] After-closing returns break AC5: stamping with the next morning's date means the 00:05 run charges one more day. Suggested: store the actual scan time and calculate fees from it.
- [Important] Return-time and nightly fee runs can collide around 00:05, double-charging or charging after return. Suggested: same unique key, plus a row lock.
- [Important] Checkout guard behaviour is undefined when the balance read fails, and AC3 needs fail-open or fail-closed chosen. Suggested: decide, log it, test it.
- [Important] Fees are irreversible with no dry-run, and no waiver or correction path; AC7 needs an append-only ledger. Suggested: shadow-run first, record corrections as ledger entries.
- [Important] AC1 is unmet: a 00:05 job misses "within one minute" of rollover. Suggested: derive the overdue state from the due date at read time.
- [Important] AC4 override: the note lacks who granted it. AC6 and AC7 have no tasks, so they lose test coverage too.
- [Minor] No handling of DST, closed days, or loans overdue when the feature launches (backfill).

## Confidence
Medium: the plan and spec are clear on these gaps, but the working directory is empty, so no code, schema or incident history was checked.
