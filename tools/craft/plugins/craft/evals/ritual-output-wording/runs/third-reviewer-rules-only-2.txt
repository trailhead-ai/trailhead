## Findings
- [Critical] No task has a test contract, and the one boundary that decides fees is never tested: the plan stamps returns scanned after closing with the next morning's date, so the fee is charged for one more day. That breaks "Returning an overdue item stops the fee from growing the same day, even if the return is scanned after closing time" (AC5), and nothing would catch it. Suggested: give each task a test contract that fails first. Include a return scanned at 23:59 and at 00:04 (just before the 00:05 job), a loan due today versus yesterday, the fee one penny under the cap and at the cap, and a fee balance of £10.00 versus £10.01.
- [Critical] The nightly job writes fees, which cannot be undone, with no idempotency, dry-run, or failure signal. A rerun or retry charges a second daily fee. A night where the job fails silently charges nothing, and nobody knows. The first run in production is also an ungated backfill: it charges every loan that is already overdue in one pass. Suggested: write one fee row per loan per date, keyed so the same day can't be charged twice. Add a dry-run mode that reports totals before charging. Stage the first backfill through the migration console. Emit a metric or alert when the job succeeds, fails, or charges an unusual total.
- [Important] The fee is computed in two places, the nightly job and the return path (Task 2). A return just before 00:05 can race the job, so the same day may be charged twice or not at all. Suggested: one function, with a uniqueness constraint on (loan, date).
- [Important] Overdue is set only by the 00:05 job, so for five minutes or more a loan isn't flagged. That misses "shown as overdue on the desk screen within one minute of the date rolling over" (AC1). Suggested: work out overdue from the due date when the screen loads, not from a stored flag.
- [Important] The override is saved as a free-text note on the borrower (Task 3). It doesn't record who granted it, and it may not show in the history. That fails "records who granted it and the reason given, and shows in the borrower's history" (AC4).
- [Important] No task covers the reminder messages (AC6) or the monthly fees report that reconciles with the ledgers (AC7). Waivers have no model at all, so reconciliation can't be tested.
- [Minor] Nothing says what happens on the nights the clocks change (DST) or when the server timezone is wrong, both of which shift the 00:05 run.

## Confidence
High. Every finding traces to a specific plan line against a spec AC; none rely on guessed scale or future state.
