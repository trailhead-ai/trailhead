**Next slice proposed for `spec/holds-and-pickup`: the hold shelf slice**

I chose this as the smallest next slice that is still worth shipping on its own. I haven't written anything for it yet. The parent task `task/the-hold-shelf-slice` doesn't exist, and planning hasn't started, so it's still cheap to turn down.

**What it's for:** When an item with a hold on it comes back, it gets put aside for the first borrower in that item's queue. That borrower gets one message giving the pickup deadline. As a result, held items stop going back onto the open shelf.

**Criteria this slice fully meets:**
- When a held item is returned, it is set aside for the first borrower in its queue and shown as on the hold shelf (AC5).
- The first borrower is sent one message that the item is waiting, naming the pickup deadline (AC6).

**Criteria it only partly meets:** None. It doesn't touch the five-hold limit with its refusal message (AC2). An earlier slice partly met that limit, and it is still a candidate for a later slice.

**Screens:** None. The slice changes what the system does when an item is returned and which message goes out. It adds or changes no screen, so there are no screen states to list.
