## Findings
- [Critical] None of the four tasks has a test contract: no task names a test or any condition that would prove it failed, so nothing pins "The daily late fee is charged per overdue item at the rate set for that item's category, and never exceeds the replacement price of the item (AC2)" or the ten-pound block. Under a production bar, the first evidence of a fee bug is a borrower who was wrongly charged or wrongly blocked. Suggested: give each task tests written first. Cover the cap boundary (just below, at, and above replacement price), a balance of £9.99, £10.00 and £10.01, and a return before and after the nightly job runs.
- [Critical] The fee calculator runs twice (task 2) and nothing makes the second run harmless. Concretely: an item is scanned back after closing on day D and stamped D+1. The 00:05 job on D+1 still sees an open loan and charges a day. The return then runs the calculator again for D+1. That is a double charge, and it also breaks "Returning an overdue item stops the fee from growing the same day, even if the return is scanned after closing time (AC5)". Suggested: write fees as ledger rows keyed by (loan, date) so a repeat run cannot add a second charge. Compute the return date from the actual scan time, not the stamped date.
- [Important] If the nightly job fails, nobody finds out. It has no health signal, alert or record of its last successful run, so one failed night leaves flags stale and fees missing without anyone noticing. Suggested: record each run and alert when the job misses a night. Make the job able to catch up on missed days.
- [Important] The 00:05 schedule cannot meet "shown as overdue on the desk screen within one minute of the date rolling over (AC1)". Suggested: work out overdue status from the due date when the screen loads, or move the job to 00:00 and make it finish in under a minute.
- [Important] Shipping the overdue flag has no migration or backfill step. Loans that are already overdue at deploy time get no flag and no fee history until a job runs. There is no way to undo the first fee run either. Suggested: run the backfill first as a dry run, then gated.
- [Important] The override note does not store who granted it, which "A librarian override records who granted it and the reason given, and shows in the borrower's history (AC4)" requires. No task covers reminder messages (AC6) or the monthly fees report (AC7) at all.
- [Minor] Two people can override at the same moment, or a checkout can happen while the job is running, and the plan doesn't say which balance the guard reads.

## Confidence
High: every finding comes straight from the plan and spec text. There is no code to check.
