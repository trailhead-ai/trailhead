## Findings

- [Critical] No task carries a test contract: the plan's own note (after-closing returns stamped next morning) plus the 00:05 fee run charges an extra day on a late-scanned return, breaking AC5, and nothing would catch it. Suggested: add a per-task contract with an injected clock, covering return at 23:59 / after closing / 00:06, fee at cap−1 / cap / cap+1, and balance at £10.00 / £10.01.
- [Critical] The nightly job is a silent, non-replayable writer of money: if the 00:05 run crashes or is skipped, no flags or fees appear and nobody is told, and a manual rerun (or the return-time recalculation) charges the same day twice. Suggested: make charges idempotent on (loan, date), emit a last-success heartbeat and alert, and add a dry-run mode and a replayable catch-up for missed dates.
- [Important] First run is an ungated backfill: every historically overdue loan may be flagged, charged and blocked at once. Suggested: decide the cutoff date and preview the totals before enabling (held below Critical only because it assumes existing overdue loans).
- [Important] AC1 is unreachable: a 00:05 job cannot flag within one minute of rollover, and a stored flag goes stale if the job fails. Suggested: derive overdue from due date at read time.
- [Important] AC6 (reminders) and AC7 (fees report, waivers, ledger reconciliation) have no task, and there is no waiver or ledger model. Suggested: add the tasks or descope explicitly.
- [Important] AC4 is not met: a free-text borrower note records no granting librarian and is not a history entry. Suggested: a structured override record with actor, reason and timestamp.
- [Important] Two concurrent checkouts, or a checkout during the fee run, can both pass the guard. Suggested: read the balance and write the loan in one transaction.
- [Minor] "00:05 local time" is skipped or repeated on DST changes or a wrong server timezone.
- [Minor] Undefined inputs: missing category rate, null replacement price, empty override reason.

## Confidence
Medium — the findings follow directly from the plan and spec text, but there was no codebase to check for existing idempotency, monitoring or tests.
