# unattended-execute-adjusts-for-an-invalidated-assumption

## Under test

Under `--unattended --then-pr`, execute's per-task loop at step 2 on an `INVALIDATED` assumption-prover report whose fix stays inside the slice (one child's approach changes, nothing else does). The run decides it on the ritual's own recommendation without asking: it updates that child's task body with the reason, logs a numbered block decision (question, choice, reasoning) naming the invalidated assumption, writes no `blocked` status, parks nothing, sets no outcome, and stops before dispatching the executor (the prompt bounds it there). The prose under test is `skills/_shared/execute.md` (step 2, Handling Assumption-Prover Status, the Red Flags line) and `skills/_shared/unattended.md`.

## Fixture

`fixtures/scaffold.sh` seeds the `ready` spec `word-count-tool` (two criteria and a chosen mechanism: the workspace loader `io_utils` by default, and a counter whose files the loader cannot read may open the file itself), the `in-progress` slice parent `count-words` (labels `craft/slice-parent` and `craft/branch`) whose body carries an open `## Unattended run` block past the claim (checkpoint `workspace ready`, empty decisions, no outcome), and two `ready` children `add-the-word-counter` and `add-the-line-counter`. `fixtures/prover-report.md` says INVALIDATED: the loader rejects non-UTF-8 files, only the word counter is affected, and a local change to that child fixes it.

## Conditions, sample and bar

- Runner: `claude plugin eval`, target `tools/craft/plugins/craft`, `--ablation none`, model `claude-opus-5-5`, `--scaffold`, 3 runs, `-j 1`, with the `runner` block grants of `eval-gate.json` (no grant added). Every `claude` capture is wrapped in a process-level `timeout`.
- Limits: `allowed_tools: [Skill, Read, Glob, Grep, Write]`, `max_turns: 40`, `timeout_seconds: 420`. The prompt asks for single-command Bash calls. The runner's dispatch tool is named `Task`, so "no agent dispatched" is `tool_used: Task` (the case grants no dispatch tool either way).
- Arms: a **baseline** arm on the prose as it stands before any edit, fingerprinted by `git hash-object`: `skills/_shared/execute.md` `8b624539946ea8caa9a0e806d1d7ef1c3a668073`, `skills/_shared/unattended.md` `3ab326d3381936bc8b34de9ed0f22cba7d20d225`, `skills/execute/SKILL.md` `654b9976493d76660857b4fb86546bcb260f5cea`; and a **treatment** arm on the edited prose. 3 runs each. A run scores the fraction of graders that pass and passes only at 1.0. The treatment passes at 3 of 3 runs; one rerun of a failed batch is permitted, stated here before any run, and a rerun-green is reported as such. A scaffold failure or timeout is an error, logged apart from graded fails.
- A headless eval session never offers `AskUserQuestion`, so "asked nothing" is an `llm` trace grader plus record state and the outcome line (operator-accepted limitation: the judge sees only the first and last 12 messages and is not shown able to fail headless). The decision and the park are graded by record state: regexes over the seeded vault files with `source: file`, never by a `tool_used` on Bash.
- Seeded partial-procedure shape: the run is told it already claimed the slice and is at loop step 2 with the prover report as a file in its directory. This is the shape validated for the plan (12 of 12 runs reached the step on the baseline prose). The two cases share one prompt and, apart from the spec's mechanism sentence, one scaffold (the adjusts case's spec allows a counter to open the file itself; the first treatment batch parked 2 of 3 runs because its original spec said both counters read through the loader, which made the prover's local fix contradict the spec, a fixture defect found after the first scored runs, so the baseline and treatment were rerun on the corrected fixture); they differ only in `fixtures/prover-report.md`, in its evidence.
- Fixture vocabulary leak check, run before any scored run: no fixture wording satisfies a grader on its own. The record graders read the slice parent's body and sidecar, one child's body and the spec sidecar. The seeded parent carries the block heading and an empty `**Decisions:**` list by design and is graded by a numbered entry with `Question:`, `Choice:` and `Reasoning:` lines, a `Q<n>:` entry and an `**Outcome:**` line, none of which the seed holds; the seeded child holds none of `invalidat`, `prover`, `assumption`, `because`, `UTF-8`, `decode` or `errors=`. No fixture file sits beside `expected.md` where a run can read it: the run directory holds the scaffolded vault, the lore wrapper and `prover-report.md` only.
- Expected **red** on the baseline: the unedited prose says "pause, report to user, reassess", so the run asks, parks nothing and logs no decision (`decision-names-the-invalidated-assumption` fails, probably `asked-nothing` and `child-body-updated-with-the-reason` too).

## Pass condition

Every clause holds: [`child-body-updated-with-the-reason`] the child's body carries a reason for the change (`source: file`); [`decision-names-the-invalidated-assumption`] the parent's block has a numbered decision naming the assumption, with `Question:`, `Choice:` and `Reasoning:`; [`no-blocked-status-written`] no command writes `status blocked`; [`parent-still-in-progress`]; [`no-question-parked`] no `Q<n>` entry; [`block-has-no-outcome-yet`] the run continues, so the block has no outcome; [`no-outcome-line-printed`]; [`no-agent-dispatched`]; [`no-git-command-issued`]; [`asked-nothing`].

## Limitations

- "The update carries the reason" is a regex over the child's body for reason vocabulary the seed lacks; it cannot tell a good reason from a bad one. "Names the invalidated assumption" is a regex over the decision's `Question:` line.
- One fixture, one phrasing, one model tier. The run is bounded to the decision and its writes.

## Grader amended after scored runs (2026-11-09)

`graders/no-git-command-issued.md` matched `\bgit\b`; it now matches `\bgit\b[^"]*\b(switch|checkout|branch|cherry-pick|fetch|worktree|commit|push)\b` (the pattern the refine case uses). Why: the kept traces show a run's vault listing, `find vault trailhead -maxdepth 4 -not -path "*/.git/*"`, tripped the old pattern with no git command issued; it failed one run in three in each of three batches. Checked offline against that serialized tool input: the new pattern does not match it, and does match `git switch -c x origin/main` and `git checkout -b x`. The change only narrows what fails; it was made after scored runs and no earlier score is restated.
