### Would build the wrong thing, needs your decision

**`fs-kiln/unload.py:3` — the cool-down hours come from a table keyed by kiln size, so a firing that ran hotter in the same kiln is marked ready too early**
Do you want each firing to carry its own cool-down time, instead of every firing in a kiln getting the same one? I recommend yes, because the board can currently tell someone to open a kiln that is still too hot.
Worst case: the change says a firing that ran hotter needs longer before it is safe to open. But `COOL_HOURS = {"large": 18, "small": 10}` gives every large-kiln firing 18 hours. A hot firing in the large kiln goes on the board at hour 18 while it still needs more time, and someone opens it early.
Fix: each firing's ready time would follow how that firing ran, not just which kiln it was in. This touches 1 file and 2 functions, `cool_hours` and `unload_time`, and removes the `COOL_HOURS` table. One caveat: the firing records only have `name`, `kiln` and `fired_at`. Nothing in them says how the firing ran, so the technician would have to start recording that before this fix can work.
*Raised by: code review*

### Would cause trouble later, worth fixing, your call

**`fs-kiln/unload.py:17` — a firing that cools exactly at this minute is left off the list; the change asks for it to count as ready, so include it**

Fix: `unload_time(firing) <= now` instead of `unload_time(firing) < now` at line 17, so a firing that cools exactly this minute counts as ready.
