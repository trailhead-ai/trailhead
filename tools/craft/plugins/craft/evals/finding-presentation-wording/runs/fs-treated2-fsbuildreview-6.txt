**`fs-kiln/unload.py:3`: the cool-down time comes from which kiln was used, not from how the firing ran.**
Should each firing carry its own cool-down time? I recommend yes. As it stands, the board can tell someone a hot kiln is safe to open. The change says a firing that ran hotter needs longer to cool, even in the same kiln. But the code looks up a fixed time per kiln (18 hours for large, 10 for small) and ignores everything else about the firing. Fix: each firing's ready time would come from how that firing ran, not from a per-kiln table. This touches 1 file and 2 functions, `cool_hours` and `unload_time`, and removes the `COOL_HOURS` table.
