## Would build the wrong thing, needs your decision

**`fs-kiln/unload.py:3` — the cool-down hours come from a table keyed by kiln size, so a firing that ran hotter in the same kiln is marked ready too early**

Should a firing's cool-down time come from the firing record instead of from which kiln it was in? I recommend yes, because as built a hotter firing goes up on the board before it is safe to open.

The committee asked for a cool-down that depends on how the firing ran, not only on which kiln it was in. The code gives every firing in a kiln the same time: 18 hours for the large kiln and 10 for the small one. Say a firing in the large kiln ran hot enough to need 24 hours. The board would call it "ready to unload" 18 hours after firing, and someone could open a kiln that is still too hot.

Fix: each firing would carry its own cool-down hours, and the board would wait that long for it. This removes the `COOL_HOURS` table and `cool_hours`, and changes `unload_time` to read the hours from the firing. One thing to check before you take it: today a firing record holds only a name, a kiln and a fired-at time. The hours have to be on that record, because the list is built from the records and the current time alone.
