**Would build the wrong thing, needs your decision (1)**

`fs-kiln/unload.py:3`: a firing's cool-down is set only by which kiln it was in. The change requires it to depend on how the firing ran. I recommend storing the cool-down on each firing record, because otherwise a kiln can be listed as safe to open while it is still too hot.
The change says a hotter firing needs longer to cool. The code looks up 18 hours for every large-kiln firing and 10 for every small one, whatever temperature it reached. So a firing that ran hot in the small kiln goes on the board after 10 hours, before it is safe to open.
Fix: each firing would carry its own cool-down hours, and the per-kiln table would go away. This touches `COOL_HOURS`, `cool_hours` and `unload_time` in `unload.py`. One catch: firing records today hold only `name`, `kiln` and `fired_at`, so whoever writes them would also have to record the cool-down.
*Raised by: code review*

**Would cause trouble later, worth fixing, your call (1)**

`fs-kiln/unload.py:17`: a firing that finishes cooling at exactly the current minute is left off the board. The change says it should count as ready. I recommend including it.
Say a small-kiln firing was fired at 23:00 and the board is built at 09:00 the next morning. Its unload time equals "now", the strict `<` comparison fails, and the firing is left off even though the committee asked for that case to show as ready.
Fix: `unload_time(firing) <= now` instead of `unload_time(firing) < now` in `ready_firings`, so a firing that cools on the minute appears as ready.
