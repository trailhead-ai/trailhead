### Would build the wrong thing, needs your decision

**`fs-kiln/unload.py:3`: the board decides when a firing is safe to open from its kiln alone, not from how the firing ran. I recommend storing each firing's own cool-down time on its record, so a hotter firing isn't announced too early.**

The change says the cool-down depends on how the firing ran, not only on which kiln it was in. The code looks the cool-down up in a table that only knows the kiln (`large` is 18 hours, `small` is 10). So a firing that ran hotter in the large kiln still shows "ready to unload" after 18 hours, and someone opens a kiln that hasn't cooled enough.

Fix: each firing's ready time would come from its own cool-down hours instead of a fixed number per kiln, and the kiln table would go. This changes `COOL_HOURS`, `cool_hours` and `unload_time` in `unload.py`. Caveat: firing records today only hold a name, a kiln and a fired-at time. Taking this fix means the technician's records need a new value for each firing's cool-down.

### Would cause trouble later, worth fixing, your call
