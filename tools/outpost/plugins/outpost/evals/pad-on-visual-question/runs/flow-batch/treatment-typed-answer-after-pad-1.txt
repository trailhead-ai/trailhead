Here's where I'd start once I can see it. The order doesn't depend on your framework:

1. **Make the step list a single piece of data.** Wizards often hard-code their steps across several places: the "Step 2 of 5" text, the next/back handlers, and the conditionals that pick which panel shows. The left-edge list needs one ordered array, something like `[{ id, label, isComplete, isReachable }]`, so the sidebar, the content area and the navigation all read from it. If the code already has that, this step is free. If it doesn't, the sidebar will drift out of sync with the steps.
2. **Pull the current step and completed steps into explicit state.** A numbered list shows done, current and upcoming steps, and you'd probably want users to be able to click back to finished ones. The usual state is a current index plus a set of completed or validated steps, rather than one counter that only moves forward.
3. **Only then build the sidebar component** and swap it in for whatever progress indicator is there now.
