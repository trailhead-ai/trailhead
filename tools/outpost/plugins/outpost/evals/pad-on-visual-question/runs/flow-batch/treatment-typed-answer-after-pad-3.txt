Here's what I'd do first, whatever the framework turns out to be:

**Make the list of steps a single piece of data.** A side list needs every step's name, its order and whether it's done or not yet reached, all available at once. A bar or a "Step 2 of 5" line only needs a counter. Most wizards I've seen have exactly that: a `step` integer and a `switch`/`if` chain that renders one screen. So the first change is a list like this:

```js
const steps = [
  { id: "company",  label: "Company details", component: CompanyStep,  isComplete: (d) => !!d.companyName },
  { id: "billing",  label: "Billing",         component: BillingStep,  isComplete: (d) => !!d.currency },
  // ...
];
```

The wizard would track `currentStepId` (or an index into that list) instead of a bare number. Then:

- the numbered side list is just `steps.map(...)` showing the label, the number and a done/current/upcoming state
- the screen being shown is `steps[current].component`
- whether a step can be clicked comes from `isComplete`, not from guesswork about earlier steps

This doesn't change how anything looks, so it's a safe change to land first. The side-list component and jumping back to earlier steps by clicking them come next and are small once this is in place.
