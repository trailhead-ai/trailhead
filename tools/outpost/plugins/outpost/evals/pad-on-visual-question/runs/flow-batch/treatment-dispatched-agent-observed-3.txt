**Recommendation: build the grid**, with event types as rows and channels as columns.

**Why:**
- **It shows everything at once.** Notification settings are really a two-way table: each event type can be on or off for each channel. The grid shows that table directly. Users can see and change "email yes, SMS no for overdue invoices" in one row, with nothing hidden.
- **Tabs per channel hide the comparison.** To check how "invoice paid" is set across channels, users have to click through every tab. People also tend to tweak one tab and never open the others.
- **A long list repeats itself.** Every topic heading repeats the same channel toggles, so the page grows by events × channels and gets tiring to scan. It's only better when each topic has its own unique settings, which notifications usually don't.
- **It fits ledgerlight's size.** A small invoicing app probably has about 3–4 channels (email, in-app, SMS/push) and 6–12 event types. That fits easily in a grid.

**Build notes:** keep the header row and the event-type column fixed in place. Add a "toggle all" control to each column header. Group the rows under short topic subheadings (Invoices, Payments, Account). On narrow screens, collapse each row into a stacked card of channel toggles.

I didn't draw sketches of the three layouts because you asked for a written recommendation.
