**Make the list of steps one shared, ordered piece of data before touching any UI.** For example, an array of `{ id, label }` that the wizard's step logic reads from. Wizards often keep "which step am I on" as a bare number, with the step names hardcoded in each screen. A left-hand list needs every step's name, plus whether each one is done, current or still to come, all in one place. Once that array exists:

1. The left list just loops over it to draw each item and its state.
2. "Next" and "Back" move through that same array, so the list and the screens can't drift apart.
3. Optionally, you can make finished steps clickable so people can jump back. That's easy to add once the steps are data rather than a hardcoded sequence.

After that, the UI work is a two-column layout: the list in a fixed left column, the current step's form on the right. On narrow screens, collapse the list to a "Step 2 of 5" line.
